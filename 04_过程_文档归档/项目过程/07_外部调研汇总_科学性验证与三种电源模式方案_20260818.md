## 第一部分：方案科学性验证（8 项结论）

### ✅ 1. CPU 满载 95.4°C 熔断 → 人为保守设计，机器本身正常

| 证据 | 数据 |
|------|------|
| 笔吧评测室 蛟龙15Pro（同模具 GM5BG0E / 同 BIOS / 同 7435H+4060）| 双烤 CPU 最高 **98.9°C** 稳定 **98.0°C**；单烤 FPU **99.1°C**/69W/4.1GHz |
| 知乎蛟龙15K 评测（2023，7735H 版）| 双烤"一秒 99°C 顶着温度墙降频，稳定不足 45W 但频率 3.5GHz" |
| AMD 官方规格 | 7435H Tjmax = 95°C（平台实际墙 ~100°C）|

**结论**: 这台机器满载顶 98-99°C 是**设计常态**（原厂狂暴模式）。你的 92°C 熔断线比原厂保守 3-7°C，牺牲 3-5% 性能换寿命余量——合理，且熔断时机正确保护了硬件。

### ✅ 2. PTM7950 换脂 → 游戏本圈公认最优解

- 知乎"波尔卡"深度实测（B 站同源）：**无上位替代**，0.2mm 片状最适合笔记本，导热系数 12W/m·K+，抗泵出、长期不衰减
- 换脂后本机实测 25W 满载仅 54°C（原厂同负载估计 60-70°C）→ **效果显著，机器状态健康**
- 注意：相变片需**热循环磨合**（约 10 次热循环性能稳定，烤一会歇一会比连续满载磨合快）

### ✅ 3. amd-pstate-epp active → 官方默认路径，正确

- Linux 6.5+ AMD Ryzen 默认 `amd-pstate` active/EPP 模式，本机 `scaling_driver=amd-pstate-epp` 即官方默认
- EPP 五档与 Windows 语义对应：performance(0x0)/balance_performance(0x40)/balance_power(0x80)/power(0xFF)
- **重要修正**: 内核动态 EPP（AC/DC 自动切换）参数为 **`amd_dynamic_epp=enable`**（非 amd_pstate=dynamic_epp=1）；Linux 7.1 合入后有回归问题、Kconfig 默认回退，修复进 7.2（2026-08-16 发布）；**dynamic_epp 启用时手动写 EPP sysfs 会失败 → 与本方案手动 EPP 切换互斥，保持手动方案，勿启用**
- governor=performance 会强制 EPP 并空转发热（acer 项目实测）→ 日常保持 powersave + EPP 控制，正确

### ✅ 4. nvidia-powerd / 140W Dynamic Boost → 官方支持，可行

- NVIDIA 官方 README（610+）：硬件要求 = 笔记本 + Ampere 或更新 GPU（4060 ✓）+ **AMD Rembrandt 或更新（7435H = Rembrandt ✓）** + SBIOS 支持；本机已确认 **Supported**
- 安装前置：驱动 ≥560（本机 595.84 ✓）；装前验证 `nvidia-settings -q DynamicBoostSupport`；复制 nvidia-dbus.conf 到 `/etc/dbus-1/system.d/` + `systemctl enable --now nvidia-powerd`
- 新驱动（610+）文档：**AC 与电池下 Dynamic Boost 均工作**（旧版仅 AC），DC 下会限制整机功耗保续航
- **收益校准**: Notebookcheck 实测 4060 游戏 ~100W 即性能拐点，115W vs 140W 游戏差异 <5%；解锁主要价值在 GPU 重计算/渲染。且 Dynamic Boost 是借 CPU 功耗给 GPU（双烤后期 GPU 140W→115W，蛟龙16K 实测）

### ✅ 5. RyzenAdj tctl_temp=92 → 官方工具、参数安全

- RyzenAdj（GitHub FlyGoat/RyzenAdj）官方确认支持 Rembrandt（SMU 56.60.0）
- tctl-temp 安全范围 **85-105°C**（超 105 可能损坏）；92°C 完全安全
- 隐藏选项 `--max-performance` / `--power-saving` **由 AC 插拔事件触发**——与三模式 AC/DC 场景切换天然契合
- **必须守护循环**: 官方 FAQ 确认部分设置会被机器电源管理覆盖 → 需 3 秒检查重写（官方 readjust.py 模式）

### ✅ 6. 离电锁频 3.1GHz → 固件级电池策略，正常现象

- 7435H 基频即 **3.1GHz**（AMD 官方规格确认）→ 离电回基频 = 电池功耗预算仅够维持基频，EC/固件行为
- 社区锁频案例（0.78/0.79GHz）均为**异常故障**（BD PROCHOT/静电），与"回基频"不同——你的离电行为**正常，非故障**
- 软件无法突破基频，三模式差异 = 锁频内的响应性 + 功耗预算 + GPU 政策

### ✅ 7. 键盘 DSDT 修复 → 与社区标准方案一字不差

- Kyanch 博客园方案（PS2K 第一个 ActiveLow→ActiveHigh + DefinitionBlock 版本号+1 + cpio acpi_override + GRUB_EARLY_INITRD_LINUX_CUSTOM）与你已做的**完全一致**
- 根因: 机革 DSDT 把键盘触发沿写反（应为下降沿），内核 ≥6.0 行为变更后失效
- 官方 BIOS N1.23A06（2024-05-13）已修复，但**仅限 7735H 系列**（XMG APEX 15 M23 通刷，7435H 严禁刷！）→ **本机 BIOS N.1.23MRO20 出厂版本无修复，DSDT override 必须保留**
- 备选: 内核 6.5+ 有 dmi 覆盖（irq1_edge_low_force_override），若主板在列表中可免 DSDT override（需确认）

### ✅ 8. 驱动备份参考（Windows ↔ Linux 映射）

| Windows 驱动 | 作用 | Linux 对应 | 需要处理？ |
|---|---|---|---|
| AmdPPM / AmdMicroPEP / amd_dpfc | AMD 电源引擎 | **amd-pstate 内核驱动**（已 active）| ❌ |
| nvhda/nvpcf/nvppc/nvtfi | NVIDIA 栈 | nvidia 驱动（已装）| ❌ |
| **GamingCenter3_Cross** | **狂暴/均衡/办公 + 风扇 + 灯光** | **无 Linux 版 → 三模式脚本替代** | ⚠️ 核心缺口 |
| uwacpidriver / hdxacptongfang | OEM ACPI/声卡 | 内核通用驱动 | ❌ |
| myappshidbus / gvinput | HID 接口/触控板 | i2c-hid | ❌ |
| netwtw08 / ibtusb | Intel WiFi/蓝牙 | iwlwifi/btusb | ❌ |

**核心结论**: Windows 电源管理 = AmdPPM + GamingCenter3；Linux 下 amd-pstate 已接管 CPU 电源，**唯一缺口 = GamingCenter 性能模式切换** → 三模式方案补位。进阶可选: TUXEDO Control Center + tuxedo-drivers（同方平台有先例，mechrevo14X-linux 已验证需加 vendor 补丁）。

## 第二部分：三种电源模式的科学划分

### 划分依据

业界统一语义（AMD EPP / Windows / RyzenAdj / Intel 平台 profile）= **供电状态（AC/DC）× 能效偏好（性能/平衡/节能）**。

与现有方案（00 文档场景 A/B/C）对应关系：

| 调研命名 | 现有场景 | 定位 |
|---------|---------|------|
| 模式 1: 带电极致性能（AC-Performance）| 场景 A | 插电游戏/渲染/编译 |
| 模式 2: 离电平衡（DC-Balanced，保持性能）| 场景 B | 离电日常办公/编程/轻度游戏 |
| 模式 3: 离电节能（DC-Power，能效优先）| 场景 C | 离电轻办公/影音/长续航 |

### 参数矩阵（调研校准版）

**模式 1: 带电极致性能（AC）**
| 参数 | 值 | 依据 |
|---|---|---|
| EPP | performance (0x00) | 最强档 |
| governor | powersave（或 performance，见 01 文档权衡）| amd-pstate-epp 下 EPP 才是控制者 |
| RyzenAdj | `--max-performance`（AC 感知）+ STAPM/FAST/SLOW 提至 65-75W | 机械革命设定 75W 上限，笔吧实测单烤 69W |
| tctl-temp | 95°C（原厂）或保守 92°C | 评测满载 98-99°C 为设计常态；92 牺牲 3-5% |
| nvidia-powerd | 启用（Dynamic Boost → 140W）| 官方支持已确认 |
| 风扇 | EC 自控（狂暴档）| |
| 预期 | 单烤 FPU ~69W/4.1GHz；双烤 GPU 140W（CPU 满载回落 115W）| |

**模式 2: 离电平衡（DC，保持性能）**
| 参数 | 值 | 依据 |
|---|---|---|
| EPP | balance_performance (0x40) | 平衡偏性能，响应好 |
| governor | powersave | |
| RyzenAdj | `--power-saving`（DC 感知）+ 可叠 STAPM=45W | AMD 默认 TDP 上限 |
| tctl-temp | 95°C 或不动 | 离电负载低 |
| nvidia-powerd | 关闭（或启用，610+ 驱动 DC 下自动限功耗）| |
| 风扇 | EC 自控 | |
| 预期 | 3.1GHz 锁频内按需 boost；续航对标 4h19m（笔吧 15Pro 实测）| |

**模式 3: 离电节能（DC，能效优先）**
| 参数 | 值 | 依据 |
|---|---|---|
| EPP | balance_power (0x80) 起步，可试 power (0xFF) | acer 项目: power 档锁 0.89GHz 极慢，从 balance_power 调 |
| governor | powersave | |
| RyzenAdj | STAPM/FAST/SLOW 降至 25-30W | 锁频基础上进一步限功耗 |
| nvidia-powerd | 关闭 | |
| 风扇 | EC 最低档（若有）| |
| 预期 | 低负载 1-2GHz；续航目标 5-7h+（轻负载）| |

### 切换机制

1. **udev AC/DC 自动切换**: `/etc/udev/rules.d/99-power-mode.rules` 监听电源插拔 → 触发对应 systemd 服务
2. **手动切换**: 三档脚本（本目录 apply_mode.sh 已有基础，可扩展）
3. **RyzenAdj 守护循环**: 3 秒检查重写防覆盖（官方 readjust.py 模式）
4. 备选参考实现: GitHub `hambosto/amd-epp`（Rust，AC/DC EPP 自动切换 + systemd 服务，GPL-3.0）

### 验证方法（沿用本目录测试体系）

- 三档分别跑 8 线程 LCG 基准 + 温度/功耗监控（turbostat/powerstat）
- 对比: 烤机功耗、温度曲线、性能分、离电续航
- 每次切换后确认 `scaling_driver=amd-pstate-epp`、EPP 已生效

## 第三部分：补充调研成果（模具/BIOS/社区证据）

1. **模具对应关系**: GM5BG0E ↔ **XMG APEX 15 M23**（Schenker/XMG 同模具，非 TUXEDO 直接对应；TUXEDO 与 XMG 同属 Schenker 集团，Linux 子品牌）→ Linux 兼容性参考 XMG APEX 15

3. **本机 BIOS = 出厂版本**（N.1.23MRO20，2024-02-06，与笔吧评测机一致）→ 无键盘修复 → DSDT override 保留必要；除非官方发布 7435H 专用新 BIOS
4. **Linux 实际使用证据**: mojira MC-303541 真实用户 GM5BG0E 跑 CachyOS 6.17.4 + KDE Wayland 正常；Arch/CachyOS 社区验证可用
5. **无核显确认**: AMD 官方规格页 7435HS "Discrete Graphics Card Required" → 独显直连是唯一路径，续航天花板低是硬件决定的（笔吧 15Pro 实测 PCMark10 4h19m，独显直连）
6. **用户体感佐证**: ZOL 用户评论"散热拉胯、原神键盘区烫"→ 散热短板是此模具公认弱点，换脂 + 温度墙管理方向正确

## 第四部分：风险与注意事项

1. **RyzenAdj 设置会被覆盖** → 必须有守护循环（不能只写一次）
2. **tctl-temp 上限 105°C**（AMD 安全红线）；95°C 熔断牺牲 3-5% 性能，是本机红线，保留合理
3. **风扇 PWM 直写 EC**（0x461/0x469）: 实测写 200 保持、写 255 可能被 EC 修正——仅紧急/测试用，日常交给 EC 自控
4. **nvidia-powerd 前置检查**: `nvidia-settings -q DynamicBoostSupport`；装上后 governor 不能锁频（它需要调频权限）
5. **140W 收益有限**: 游戏 ~100W 即拐点（Notebookcheck）；价值在 GPU 重计算
6. **离电 Dynamic Boost**（610+ 驱动）: DC 下自动限制整机功耗，与模式 2/3 的 EPP 叠加需实测确认不冲突
7. **动态 EPP 互斥**: 勿启用 `amd_dynamic_epp`（启用后手动 EPP 写入失败，且 7.1 有回归、7.2 才修好）
8. 键盘 DSDT 修复与电源方案无关，不受影响；BIOS 升级前务必确认 7435H 专用版本
