# 03_场景C_离电极限续航.md — 离电轻办公（极限续航，保留基本性能）

> **目标**: 离电时文字/网页/文档 5-7h+，日常操作仍可用（不卡死）
> **手段**: EPP=power + Turbo OFF + 频率上限 + GPU 低功耗墙 + TLP 激进 + 屏幕最低可用亮度
> **铁律**: 先读 00 文档；本场景是"省电压榨"，验证时必须测续航数据，不得凭感觉

---

## 一、设计逻辑

7435H 无核显 → 显示功耗固定（GPU 空闲 ~5-8W 实测）。剩余可压空间：
1. **CPU 包功耗**：EPP=power + Turbo OFF + 频率上限 → 空闲可从 ~8-10W 压到 ~4-6W；
   满载从 80W 压到 ~20-25W（文档类负载几乎不感知）。
2. **GPU**：RTD3 已负责空闲（实测 ~2W）；手动 -pl 无效（见 04 陷阱 11），GPU 峰值功耗由固件/nvidia-powerd 管理。
3. **外设**：USB 自动挂起、蓝牙关、WiFi 节能、屏幕 25-40% 亮度（最大单项杠杆）。
4. **可选 RyzenAdj**：EC 默认离电策略可能已限 TDP（贴吧有"离电锁频"反馈），RyzenAdj 可**加严**功耗墙兜底。

---

## 二、实施步骤（按序）

### 步骤 1: TLP 极限续航配置（/etc/tlp.conf 追加/覆盖）

```ini
# ===== CPU =====
CPU_SCALING_GOVERNOR_ON_BAT=powersave
CPU_ENERGY_PERF_POLICY_ON_BAT=power
CPU_BOOST_ON_BAT=0                      # 关 Turbo（单核省电关键）
CPU_SCALING_MIN_FREQ_ON_BAT=800000      # 最低 800MHz（空闲兜底，避免 411MHz 卡顿）
CPU_SCALING_MAX_FREQ_ON_BAT=2400000     # 上限 2.4GHz（覆盖 95% 办公需求；可调 2.0-3.0GHz 权衡）

# ===== USB / PCI =====
USB_AUTOSUSPEND=1
USB_AUTOSUSPEND_DISABLE_ON_SHUTDOWN=1
RUNTIME_PM_ON_BAT=auto

# ===== 磁盘 =====
DISK_APM_LEVEL_ON_BAT="64 64"          # NVMe 激进 APM（配合 APST）

# ===== WiFi =====
WIFI_PWR_ON_BAT=on

# ===== 蓝牙 =====
# tlp-rdw 负责: sudo tlp-rdw 4 (全关)
```

```bash
sudo systemctl restart tlp
sudo tlp-stat -p    # 验证: governor=powersave, EPP=power
```

### 步骤 2: 屏幕与外设

```bash
echo 30 | sudo tee /sys/class/backlight/nvidia_0/brightness    # 25-40% 视环境
sudo systemctl disable --now bluetooth
# Cinnamon: 离电 3 分钟关屏 / 10 分钟休眠
```

### 步骤 3: GPU 功耗管理（2026-08-17 实测修正）

**实测结论**：`nvidia-smi -pl 30` **无效**（SBIOS 未开放手动写入，见 04 文档陷阱 11）→ 已移除。
GPU 侧实际省电手段仅剩：
```bash
# 1) RTD3 空闲休眠（已启用，无需操作）——空闲 ~2W
# 2) nvidia-powerd（已启用）——空闲锁基础墙，3D 按需释放
# 3) 场景 C 下最有效：屏幕亮度（已降 30%）+ 避免 3D 负载
```

### 步骤 4: 可选 — RyzenAdj 功耗墙加严（进阶）

若实测空闲功耗仍偏高（>10W），或想硬性限制满载功耗（如多人共享/充电器没带）：

```bash
# 安装编译（见 05 文档）; 设置 CPU 包功耗上限 20W + 温度墙 85°C
sudo ryzenadj --stapm-limit=20000 --fast-limit=25000 --slow-limit=20000 --tctl-temp=85
sudo ryzenadj --info | head -20    # 回读验证
```

⚠️ Rembrandt 上 stapm-limit 为"部分支持"（GitHub Wiki #197），若回读失败/无变化，
只用 `--fast-limit/--slow-limit/--tctl-temp`（✅ 支持）。不做电压操作（铁律 4.5）。
设置不持久 → 用 systemd 服务固化（05 文档有模板）。

### 步骤 5: 电池保护（长期插电用户）

TLP 充电阈值需硬件支持（本机 EC 无 tuxedo 接口，标准 TLP 阈值**大概率不可用**——验证：
`sudo tlp-stat -b` 若显示 threshold 支持则配置）：

```ini
# 仅当 tlp-stat -b 显示硬件支持时才启用:
# START_CHARGE_THRESH_BAT0=60
# STOP_CHARGE_THRESH_BAT0=80
```

不支持时的人工策略：避免长期 100% 满电插电；隔几周放一次电到 30-50% 再充满（校准）。

## 三、验证协议

| 指标 | 目标 | 工具 |
|------|------|------|
| 离电空闲功耗 | **≤8W**（理想 5-7W） | `powerstat 5 24`（拔电） |
| 离电轻载功耗 | ≤15W（浏览器+文档） | powerstat |
| 续航 | **5-7h+**（实测放电） | 记录时间/电量斜率 |
| 满载频率 | ≤2.4GHz（被限） | stress-ng + 采样 |
| 满载温度 | ≤75°C（功耗墙 20W 下应 ~60-70°C） | sensors |
| 可用性 | 文档/网页流畅，视频 1080p 不卡 | 日常使用 |

# 例: 5 分钟掉 1% → 满电 500 分钟 ≈ 8.3h（线性外推仅参考, 实际负载波动）

## 五、风险清单

| 风险 | 等级 | 缓解 |
|------|------|------|
| 频率上限过低 → 应用卡顿 | 低 | 从 2.4GHz 起；卡顿则升 2.8-3.0GHz 或 EPP 改 balance_power |
| Turbo OFF 后单核编译/网页 JS 变慢 | 低 | 本场景面向轻办公；重活切场景 A |
| RyzenAdj 部分参数不生效 | 低 | 回读验证；只信 fast/slow/tctl |
| s2idle 睡眠耗电（本机无 S3） | 中 | 长时间离电不用 → 关机/休眠（`systemctl hibernate` 若 swap 配置好） |
| 3D 负载触发 Dynamic Boost 抬升功耗 | 低 | 场景 C 避免 3D 负载；如需要则切场景 B/A |
