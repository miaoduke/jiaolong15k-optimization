# 蛟龙15K 控制台软件——详细规划（2026-08-21）

## 一、调研总结

### 1.1 本地官方控制台（ControlCenter 5.17.49.19，已完整反编译）
架构：UWP(AOT) → MQTT → Systray → GCUService → ACPIDriverDll → UWACPIDriver.sys → EC
功能全景：
| 模块 | 官方功能 |
|---|---|
| RGB | 28 灯效（Single/Breathing/Wave/.../BatteryPercent=35/Music=34/Manual=64）、AC/DC 分离、亮度5档、欢迎灯、音乐律动 |
| 平台 | Gaming/Office/Turbo/Custom/Benchmark 5 档 |
| 风扇 | Boost、用户风扇5档、智能风扇表 |
| 功耗 | PL1/2/4 档、CPU超频(本机锁死)、VRM电流 |
| 电池 | 充电阈值(0x7B9)、健康、电量灯 |
| 硬件 | 触控板、摄像头、Win锁、飞行模式、麦克风、宏键 |

### 1.2 网络热门控制台
| 项目 | 架构 | 适用性 |
|---|---|---|
| TUXEDO Control Center | Electron + Node daemon + tuxedo-drivers | ✗ 重量级 + 依赖非 mainline 驱动 |
| asusctl + rog-control-center | Rust daemon + dbus + Gtk GUI | ✗ 华硕硬件专用 |
| system76-power | GNOME 原生 + power-profiles-daemon | △ 只有平台模式(已被 uniwill 覆盖) |

**结论**：无现成可用，自研轻量 Gtk3 控制台最合理（本机已用 mainline uniwill 驱动 + 全套脚本）。

### 1.3 本机 API 基础（uniwill 驱动 + 已有脚本）
sysfs 接口（INOU0000:00 平台设备）：
```
platform-profile        quiet|balanced|performance
rainbow_animation       0|1
breathing_in_suspend    0|1
fn_lock_toggle_enable   0|1
super_key_toggle_enable 0|1
touchpad_toggle_enable  0|1
```
LED（/sys/class/leds/uniwill:multicolor:）：
```
kbd_backlight: brightness 0-4 + multi_intensity "R G B"
status:        机器状态灯
```
hwmon5：temp1=CPU / temp2=GPU / fan1=Main / fan2=Secondary / pwm1 / pwm2

已有脚本（复用，不重写）：
| 脚本 | 功能 |
|---|---|
| kbd_rgb.py | 静态色/彩虹/呼吸/status |
| platform-mode.sh | 平台模式循环切换+通知 |
| power-mode.sh | 四维联动（自动） |
| charge_limit.sh | 充电阈值 |
| power-status.sh | 状态总览 |
| kbd-battery.sh | 电量灯轮询 |
| ryzenadj | 功耗管理 |

## 二、架构设计

### 2.1 总体架构（Ponytail：单进程，无 daemon）
```
┌─────────────────────────────────────┐
│  jcc.py（单文件 PyGObject/Gtk3）      │
│  ┌──────────┬──────────┬──────────┐ │
│  │ 性能页    │ RGB页     │ 硬件页    │ │
│  └────┬─────┴────┬─────┴────┬─────┘ │
│       │  sudo -n 调用            │    │
├───────┼──────────┼──────────────┼────┤
│ platform-mode │ kbd_rgb.py  │ sysfs  │
│ power-status  │ kbd_battery │ 写属性  │
│ charge_limit  │            │         │
└───────────────┴────────────┴────────┘
```

理由：
- 已有脚本封装了所有 root 操作，GUI 只做展示 + 调用
- sudoers 免密（扩展现有 platform-mode 先例）
- 无 daemon = 无内存常驻（省电理念一致，反 TCC Electron 之道）

### 2.2 权限方案
扩展现有 /etc/sudoers.d/ 免密：
```
<USER> ALL=(root) NOPASSWD: /usr/local/bin/platform-mode.sh, /usr/local/bin/kbd_rgb.py, /usr/local/bin/charge_limit.sh, /usr/local/bin/power-status.sh, /usr/bin/tee
```
（sysfs 写属性用 `echo x | sudo tee` 或 python 内 sudo）

## 四、技术选型
| 项 | 选择 | 理由 |
|---|---|---|
| GUI 框架 | PyGObject/Gtk3 | 已可用，Cinnamon 原生 |
| 语言 | Python3 | 已有脚本同栈 |

## 六、分阶段实施
### Phase 1（MVP，核心可用）
- 性能页：平台模式切换 + 温度/风扇/电池状态 + 充电阈值
- RGB 页：静态色（预设8色）+ 亮度
- 窗口 + 三页 Notebook

### Phase 2（完整）
- RGB：彩虹/呼吸动画 + 电量灯开关 + 色轮
- 硬件页：触摸板/Win锁/呼吸挂起
- 状态实时刷新（1s）

### Phase 3（体验）
- 托盘图标（AppIndicator）最小化
- 开机自启（可选）
- 通知集成（切模式 notify-send）

## 七、验收标准
1. 平台模式三档切换即时生效（读回验证）
2. RGB 静态色/亮度即时生效（EC 读回验证）
3. 温度/风扇/电池数据与 power-status.sh 一致
4. 充电阈值写入成功（charge_limit 读回）
5. 无内存常驻（退出后进程消失）
6. 非 root 用户可运行（sudo 免密工作）

## 八、风险与边界
- 不做：CPU 超频（硬件锁死）、用户风扇5档（驱动覆盖）、单键背光（0x78C 风险）、摄像头（驱动未暴露 sysfs）
- 28 灯效只实现硬件支持的 4 类（静态/彩虹/呼吸/电量灯），其余为 ROW/PICTURE 软件模拟（AP 类）价值低
- 状态轮询 1s 可能有 GPU 唤醒开销——用 hwmon（EC 直读）不用 nvidia-smi 高频轮询
