## 二、十大大信息陷阱（本机风险清单）

### 陷阱 1: 目录旧文档是 Intel 专属，直接套用 ⚠️⚠️⚠️（最高优先级）
`性能优化方案/` 全部基于 i5-8250U: intel-undervolt / MSR 0x1A0 / PL1-PL2 / intel_pstate / MX150 独显切换。
**本机是 amd-pstate-epp + 无核显 + RTX4060**，唯一可复用：方法论（红线/采样/备份/变量控制）。

### 陷阱 2: 刷 BIOS 通刷包 🔥🔥🔥（硬件风险）
贴吧/B站流传"蛟龙15/16/17K 用 XMG APEX 15 M23 BIOS 通刷"——**仅 7735H 可用**。
7435H 刷 7735H BIOS = **不开机**（S12 实锤）。本机 BIOS N.1.23MRO20 (2024-02) 已含 RembrandtPI，**零需求**。

### 陷阱 3: "Dynamic EPP 内核会自动切换" 
Linux 7.1 引入 amd-pstate Dynamic EPP（AC/DC 自动切 EPP）——**本机内核 7.0.0-28 无此功能**（S1）。
且 7.1 初版有性能问题，7.3 才重做为每核粒度。本机必须 **TLP/脚本手动管理 EPP**（本方案做法）。

### 陷阱 4: "GPU 115W = 被阉割/有问题"
NVIDIA 官方+多源一致（S4/S5/S15）：**115W 是基础墙，140W 是 Dynamic Boost 上限**，空闲锁 115W 属正常设计。
Windows 游戏到 140W 靠 nvidia-powerd 等效机制；Linux 启用 nvidia-powerd 即可（场景 A 步骤 2）。
另有案例（Dell/HP）需 BIOS 性能档或 Fn+Q 配合——本机有 Fn+X（待验证）与 platform_profile（无接口），
若 nvidia-powerd 后仍锁 115W，参照 S5 排查 EC 模式。

### 陷阱 5: "TLP 和 power-profiles-daemon 可以共存"
TLP 官方 + 2026 多篇实测：**两者冲突**（同改 USB/PCI 参数互踩）。本机现状已装 PPD →
本方案：**TLP 启用则停 PPD**（二选一，05 文档有命令）。Framework/AMD 官方建议 PPD 的说法
基于有 platform_profile 的机器；**本机无此接口**（实测 /sys/firmware/acpi 无 platform_profile），
PPD 价值大打折扣，TLP 更优（S8/S9/S13 共识）。

### 陷阱 6: "governor=performance 就是全速 + EPP 生效"
TLP FAQ 实证（S9）：**governor=performance 会锁死 EPP=performance**——看似没问题，实则在离电时
CPU 永远全速策略。本机当前就处于此状态（实测 EPP 全 performance）。离电必须 governor=powersave。

### 陷阱 7: "RyzenAdj 可以像 Intel 机那样调电压"
RyzenAdj FAQ/Wiki（S3）：**Rembrandt 移动端无可靠电压控制**；stapm-limit 也仅部分支持。
本方案铁律：**RyzenAdj 只用于功耗墙/温度墙，不做电压**。目录里"电压只能为负"简化为"不做电压"。

### 陷阱 8: "第三方机械革命 Linux 驱动直接可用"
wujie14-kmod / tuxedo-drivers 魔改版（S10）针对**无界系列（IP3 xN39 / 14X 等特定模具）**：
依赖特定 WMI GUID。本机实测 WMI 仅标准 GUID（05901221…/ABBC0F6A… 等）→ **不适用**。
Fn+X 模式切换是 EC 硬件处理（OS 无关），本机理论上可用但需验证（见 01 文档步骤 4）。

### 陷阱 9: "硅脂片 = 省事方案"（继承目录结论，本机同样适用）
目录 00_交接手册已深度甄别（PTM7950 相变片 vs 普通硅胶垫）——本机 7435H 为**裸 Die**，
若未来清灰换脂必须用相变片（PTM7950），普通硅胶垫是降级。本方案不涉及换脂，仅留作散热预案。

### 陷阱 10: "Linux 下 4060 被限 80W"（部分论坛说法）
部分机器（特定 BIOS/EC）在 Linux 被限 55-85W（S5 多帖）——**本机实测不同**：
`nvidia-smi` 显示 Min=5W / Current=115W / Max=140W，功耗墙接口完整开放。
但**不排除 3D 负载时仍被 EC 约束**（Dynamic Boost 需 firmware 放行），场景 A 验证协议已覆盖此风险。

### 陷阱 11: "nvidia-smi 显示可调范围就能改功耗墙" 🔥（2026-08-17 本机实测戳穿）
`nvidia-smi` 显示 Min=5W / Max=140W，但 **`nvidia-smi -pl 60` 实际被拒**：
```
Changing power management limit is not supported for GPU: 00000000:01:00.0.
Treating as warning and moving on.
```
**该命令返回 0（"成功"）但墙不变**——脚本里 `&&` 判断会误报成功（本次实测教训）。
原因：本机 SBIOS 未开放手动功耗墙写入（与部分 Dell/HP 相同），**功耗墙只能由固件/nvidia-powerd 管理**。
→ 场景 B/C 的"手动 -pl 降墙"步骤**无效**，已从方案移除；GPU 省电仅靠 RTD3（空闲自动 D3）+ powerd。
→ 教训补充到铁律：**写入后必须回读验证**（nvidia-smi 本例：回读发现 Requested=115 未变）。

### 陷阱 12: "出问题=系统重启"（2026-08-17 事件记录）
外接数据盘（nvme0n1p5, NTFS, DE063C1F）在系统异常后**未自动挂载** → 数据"消失"。
实况：`lsblk` 显示分区存在但 MOUNTPOINT 为空；`mount -t ntfs-3g` 手动挂载即恢复。
**预防**: 开机后检查 `lsblk`/`ls /media/<USER>/<DATA_PART_UUID>/`；异常后先查挂载再下结论。
（与目录 00_交接手册"数据盘不自动挂载，需手动 mount"记载一致——本机已知问题。）

## 四、结论

1. **本机可优化空间真实存在**：当前 EPP 锁 performance（离电耗电）、GPU 未启用 Dynamic Boost（AC 少 25W）、
   PPD 无 platform_profile 可用（空转）。
2. **三场景手段均基于官方/权威来源**，且以本机实测 sysfs 值为准，无跨机型照搬。
3. **最大的两个风险**（刷 BIOS、做电压）已被铁律直接排除；其余风险均有回滚路径。
4. **遗留待验证项**（不影响方案主体，标注在 05 手册）：Fn+X 三模式可用性、nvidia-powerd 实际解锁效果、
   RyzenAdj 在 Rembrandt 的 stapm 支持实测、离电功耗基线。
