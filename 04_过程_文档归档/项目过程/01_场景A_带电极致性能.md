# 01_场景A_带电极致性能.md — 插电游戏/渲染/编译

> **目标**: 插电时 CPU/GPU 全力释放，达到或接近评测水平（CPU 满载 80W@4.1GHz、GPU 140W Dynamic Boost）
> **前提**: 本机 RTX 4060 是 115W 基础墙 + 25W Dynamic Boost（=140W Max），评测"满血 140W"需解锁动态墙
> **铁律**: 先读 00 文档；所有写入先记录原值；满载遵守安全红线（>75°C 拒测 / >92°C 停 / >95°C 熔断）

---

## 一、当前问题（实测）

1. **GPU 被锁在 115W 基础墙**：`nvidia-smi` 显示 Current=115W，评测/Windows 下可到 140W。
   原因：Dynamic Boost 需要 nvidia-powerd 守护进程，**本机未安装**。
2. **CPU EPP=performance 已是全速**：AC 场景无需改动 governor（performance 锁 EPP 在此场景是"正确行为"）。
3. **散热状态：原厂硅脂（持续使用，换脂计划已取消）**。评测（原厂硅脂）单烤 FPU 97.5°C@80W；
   本机满载基线已实测（见 08 报告：温度墙 92°C 后满载 3.7-3.9GHz 稳定）。
   温度管理由 ryzenadj-watch 守护（默认 92°C，可 `脚本/set_tctl.sh` 调整），不做硬件改动。

## 二、实施步骤（按序）

### 步骤 1: 建立 AC 满载基线（必做，~10 分钟）

```bash
# 1. 确认环境温度 + GPU 空闲态
sensors | grep -i acpitz
nvidia-smi --query-gpu=utilization.gpu,temperature.gpu,power.draw

# 2. 温度 ≤65°C 后跑满载（1s 采样 + 20s，铁律 4.2）
# 注意观察：满载温度、满载频率（评测参考：~4.1GHz / 80W）
# 若 >92°C → 立即停止，冷却 120s（守护墙默认 92°C，可 set_tctl.sh 调整）
# 若 ≤85°C → 原厂散热健康，继续本场景
```

记录到 CSV：`基线_AC_EPP_perf_原厂散热` 温度起止 / 满载频率 / RAPL 功耗。
基线数据见 08 报告（已实测完成）。

### 步骤 2: 启用 nvidia-powerd（解锁 140W Dynamic Boost）

```bash
# 安装（Ubuntu/Mint 仓库有 nvidia-powerd，与驱动同源）
sudo apt install nvidia-powerd

# 拷贝 dbus 配置（NVIDIA 官方文档步骤，缺它 daemon 无法注册）
sudo cp /usr/share/doc/NVIDIA_GLX-1.0/nvidia-dbus.conf /etc/dbus-1/system.d/ 2>/dev/null \
  || echo "nvidia-dbus.conf 不存在则跳过（新驱动可能已内置）"

# 启用并启动
sudo systemctl enable --now nvidia-powerd
sudo systemctl status nvidia-powerd
```

**验证 Dynamic Boost 生效**：
```bash
# 空载时仍是 115W（正常，官方说明：空闲锁基础墙省电）
nvidia-smi -q -d POWER | grep -E "Power Limit|Power Draw"

# 3D 负载时观察墙上探（跑 glxgears / 游戏 / blender 渲染时另开终端）：
watch -n1 "nvidia-smi --query-gpu=power.limit,power.draw,utilization.gpu --format=csv"
# 若游戏时 power.limit 上探至 ~140W → Dynamic Boost 生效 ✅
```

> 注意：若某些游戏帧率异常或功耗不升，检查是否需 Fn+X 狂暴模式（见步骤 4）。

### 步骤 3: TLP AC 配置（可选但推荐，保证 AC 下不误伤性能）

```bash
sudo apt install tlp tlp-rdw
sudo systemctl stop power-profiles-daemon && sudo systemctl disable power-profiles-daemon

# /etc/tlp.conf 关键项（AC 部分）:
#   CPU_SCALING_GOVERNOR_ON_AC=performance
#   CPU_ENERGY_PERF_POLICY_ON_AC=performance
#   CPU_BOOST_ON_AC=1
#   CPU_SCALING_MIN_FREQ_ON_AC=0
#   CPU_SCALING_MAX_FREQ_ON_AC=4554000
sudo tlp start && sudo tlp-stat -p   # 验证
```

> 注意：TLP 默认 `CPU_SCALING_GOVERNOR_ON_AC` 已是 performance，EPP 默认 balance_performance；
> 本场景显式写 performance 保证全速。TLP 与 PPD 冲突铁律：**TLP 启用时必须停用 PPD**（05 文档有完整步骤）。

### 步骤 4: Fn+X 硬件模式（狂暴/均衡/安静，EC 层，与 OS 无关）

同方/机械革命模具的 Fn+X 由 **EC 硬件处理**（无需任何驱动），本机应可用：
- 切换到"狂暴模式"再跑满载验证。
- ⚠️ **待验证项**：本机 Fn+X 是否映射三模式（狂暴/均衡/安静）。验证方法：
  - 切换后满载观察 CPU 频率/功耗是否变化（狂暴应更高）；
  - 无变化则说明本机 BIOS 未开放 EC 模式切换（不影响本方案，只影响上限）。
- 注意贴吧反馈："蛟龙15K 锐龙 7435H 不插电卡顿锁频问题"——那是 **Windows 下 EC 离电策略**，
  与 AC 场景无关；Linux 下离电性能由 EPP/TLP 管理（见 02/03 文档）。

### 步骤 5（可选，进阶）: RyzenAdj 温度墙管理

本机 Rembrandt 支持 tctl-temp（✅）。若满载温度逼近 95°C 但不想降性能，
可设置温度墙让 SMU 自动平衡（评测 97.5°C 是原厂状态，不建议复刻）：

```bash
# 查看当前（需 root; /dev/mem 后端本机可读）
sudo ryzenadj --info | head -20

# 示例：温度墙 92°C（保守，留给散热余量）
sudo ryzenadj --tctl-temp=92

# 需要更高 PPT（若散热极好，评测单烤 80W 是 EC 默认；RyzenAdj 可提升 fast-limit）：
sudo ryzenadj --fast-limit=90000 --slow-limit=65000 --stapm-limit=65000   # ⚠️ 进阶, 慎用
```

⚠️ **RyzenAdj 铁律**：不做电压；stapm-limit 在 Rembrandt 仅"部分支持"（GitHub Wiki 实测），
改后必须 `--info` 回读确认；设置不持久，重启失效（可通过 systemd 服务固化，见 05 文档）。

## 三、验证协议（对照评测基准）

| 指标 | 评测参考（笔吧评测室 2024-05） | 本机验证目标 | 工具 |
|------|-------------------------------|-------------|------|
| CPU 单烤频率 | 4.1GHz @ ~80W | ≥3.8GHz 满载 | stress-ng + 1s 采样 |
| CPU 单烤温度 | 97.5°C（原厂硅脂） | ≤92°C（本机若新硅脂应更低） | sensors k10temp |
| GPU 满载功耗 | 140W | 3D 负载下 power.limit=140W | nvidia-smi watch |
| GPU 满载温度 | 86°C | ≤88°C | nvidia-smi |
| 双烤总功耗 | ~190W | ≥180W 无明显掉电 | nvidia-smi + RAPL |

**通过标准**：CPU ≥3.8GHz 且 ≤92°C；GPU 3D 下 140W 墙生效。不达标 → 记录数据、冷却、检查步骤 2/4。

## 四、回滚

```bash
# GPU 功耗墙回默认（若手动改过）
sudo nvidia-smi -pl 115

# 停用 nvidia-powerd
sudo systemctl disable --now nvidia-powerd

# TLP 恢复出厂配置
sudo tlp-stat -c    # 查看当前
# 或恢复备份的 /etc/tlp.conf

# 停用 TLP 恢复 PPD
sudo systemctl enable --now power-profiles-daemon && sudo systemctl stop tlp
```

## 五、风险清单

| 风险 | 等级 | 缓解 |
|------|------|------|
| 满载温度 >95°C（散热老化/积灰） | 中 | 先基线测试；超限 → 清灰换脂（PTM7950 方案见目录） |
| Dynamic Boost 使 CPU 侧降频（总功耗 190W 超适配器） | 低 | 官方设计行为；若体验差可停 nvidia-powerd 回 115W |
| Fn+X 不可用（BIOS 未开放） | 低 | 不影响方案主体；仅损失 EC 额外上限 |
| RyzenAdj 参数不被 Rembrandt 接受 | 低 | 回读验证，失败即恢复默认（重启自动重置） |
