- 编制: 2026-08-20（七轮全面调研后定稿）

## 一、调研成果总览（关键结论）

| 领域 | 结论 |
|------|------|
| EC 架构 | 4K 空间全穷尽：0x700-7FF 功能寄存器 + 0xF00-0xF5F 风扇表可操作；其余为校准/镜像数据 |
| EC 基址 | 0xFED50000（DSDT ECMG）——read_mem 直读恢复，ec_tool.py 已修复 |
| RGB 协议 | 官方验证：0x769-76B 颜色 + 0x767 bit5 应用/bit7 彩虹；0x76C-76E 非持久（实验淘汰） |
| 风扇表 | CPU/GPU × 表1(0xF00/0xF30)+表2(0xF20/0xF50)；模式切换只改表2；单位≈PWM%（3800RPM=100%） |
| 平台模式 | platform_profile 现成接口；性能/平衡共用一套表；quiet 独立（上限 110 vs 150） |
| 降压/超频 | 硬件锁死（SMU 拒 CO/OC/VID）——不做 |
| 键盘 | DSDT IRQ 极性 override 修复已验证生效（8/18 修复包完整） |
| 电源栈 | amd-pstate-epp 已 active；TLP 配置基本合理（AC 档 governor 偏激进可优化） |
| 启动 | 25.6s；wait-online 5.8s 最大可优化项 |
| 电池 | 循环 23 次、健康 100%、阈值 80% 生效、校准 3800RPM |
| 已知陷阱 | Bug 218305：s2idle 恢复后 CPU 卡 544MHz（遇性能骤降即知） |

## 二、改进方案（按优先级）

### P0-1 禁用 NetworkManager-wait-online.service（省 5.8s 启动）
- 收益: 启动 25.6s → 19.8s（-23%）；桌面无网络依赖
- 风险: 低（服务器场景才需要等待网络就绪）
- 操作:
  ```bash
  sudo systemctl disable NetworkManager-wait-online.service
  ```
- 验证: `systemd-analyze` 对比
- 回滚: `sudo systemctl enable NetworkManager-wait-online.service`

### P0-2 移除打印机并口模块（省 ~2s 于 modules-load）
- 收益: modules-load 4.1s 缩短（本机无打印机）
- 操作:
  ```bash
  sudo rm /etc/modules-load.d/*.conf 中 lp/ppdev/parport_pc 行
  # 或: sudo truncate -s 0 /etc/modules-load.d/printers.conf（若存在）
  ```
- 验证: `systemd-analyze blame`；`lsmod | grep parport` 消失
- 回滚: 恢复原行
- 注意: uniwill-laptop / led-class-multicolor 必须保留

### P0-3 禁用 gpu-manager.service（省 3.5s）
- 收益: Ubuntu 遗留的 GPU 配置器，Mint 上无用
- 操作: `sudo systemctl disable gpu-manager.service`
- 风险: 低（NVIDIA 驱动由 dkms 管理）

### P0-4 禁用 blueman-mechanism.service（省 1.7s）
- 收益: 蓝牙服务 inactive 却自启客户端守护
- 操作: `sudo systemctl disable blueman-mechanism.service`
- 回滚: enable 恢复

### P0-5 禁用 casper-md5check.service（省报错+启动）
- 收益: Live ISO 校验服务桌面无用、启动报错
- 操作: `sudo systemctl disable casper-md5check.service`

### P0-6 TLP AC 档 governor 调整（省电，性能几乎无损）
- 依据: AMD 推荐 amd-pstate-epp 下 governor=powersave + EPP=balance_performance（单核 boost 需要其他核降频让路；performance governor 全核满频费电）
- 操作: /etc/tlp.conf
  ```
  CPU_SCALING_GOVERNOR_ON_AC=powersave
  CPU_ENERGY_PERF_POLICY_ON_AC=balance_performance
  ```
- 验证: `cpupower frequency-info` + 跑分对比（预期损失 <2%）
- 风险: 低（可逆）；若感知性能下降可回 performance

### P0-7 键盘灯电量显示（BatteryPercent 灯效）
- 收益: 官方灯效之一，离电时键盘灯显示电量（实用生态功能）
- 方案: 脚本读 EC 电池%（0x3E 区/或 sysfs）→ 映射颜色 → 写 0x769-76B + 触发
- 风险: 低；注意与 kbd-rgb-restore 服务协调

### P0-8 平台模式切换 UI（一行脚本+通知）
- 收益: 免 BIOS/快捷键，桌面一键切 quiet/balanced/performance
- 方案: 写 /sys/firmware/acpi/platform_profile + notify-send
- 风险: 无（内核接口）

## 三、明确不做（详细清单与科学依据）

### 1. 降压/超频（CPU Undervolt/Overclock）
**不做。原因：硬件锁死，无可行路径。**
- 实测证据（三次独立验证）：
  - `ryzenadj --set-coall=-5`（-5mV）→ SMU 拒绝（BIOS 未开放 CO）
  - `ryzenadj --enable-oc=1` → 拒绝
  - `--oc-volt` → 家族不支持（Rembrandt 移动端 BIOS IF 18 无该功能）
- 网络确认：AMD 移动 H 系（非 HS/X）降压普遍锁死；Framework 论坛实测 offset 被 boost 反补偿，收益≈0
- 唯一理论路径 Smokeless_UMAF（改 BIOS 开 CO）→ 高风险、无 7435H 先例 → 不碰

### 2. BIOS 修改（Smokeless_UMAF / 第三方 BIOS）
**不做。原因：风险>收益。**
- 本机 BIOS 为 AMI 32MB（N.1.23MRO20 2024-02-06），Smokeless_UMAF 理论支持
- 但唯一值得开的项（降压）已被 SMU 锁死 → 修改无实质收益
- 变砖风险 + 机械革命不提供恢复工具；官方只认 7435H 版本（严禁刷 7735H 通刷——会不开机）
- 键盘 IRQ 问题已用 DSDT override 解决（无需动 BIOS）

### 3. 灯条（Lightbar）/ 静音模式（Silent Mode）
**不做。原因：硬件无此功能。**
- EC 支持位实测：0x765=0xA1（飞行/FanBoost/SuperKey ✓，无 lightbar/OC/macro 位）
- 0x766=0xB4（RGB/中国模式/我的电池 ✓，无 silent/USB 充电位）
- 驱动源码特征位同样未定义 → 固件层面就不存在，任何尝试都是死路

### 4. 0x76C-76E 默认色寄存器（开机默认键盘色）
**不做。原因：实测非持久，被 EC 固件管理。**
- 实验过程：写蓝(0,0,50) → 读回成功 → 但灯色不变；重启后 0x76C-76E 被 EC 重置回青(0,50,50)
- 结论：该区是 EC 固件内部缓冲，不由 OS 控制；开机色只能靠 kbd-rgb-restore 服务在启动后写入
- 保留现状：kbd-rgb-restore.service 是唯一可靠方案（已部署）

### 5. 驱动 touchpad_toggle_enable（触摸板切换）
**不做。原因：上游已知失效功能。**
- Armin Wolf 驱动源码/PATCH 说明中明确标注该功能不可靠
- 本机触摸板切换已有自己的 acpid+xinput 方案（8/18 修复包，验证通过）
- 不重复造轮子

### 6. 风扇表 1 修改（0xF00/0xF10/0xF30/0xF40）
**不做（当前阶段）。原因：驱动与模式管理，擅自改会被覆盖且风险高。**
- 表 1 由平台模式（platform_profile）固件管理——切模式即重写
- 温度端点影响全系统热策略，改错可能导致风扇失控/过热
- 表 2（0xF20/0xF50）是驱动未覆盖的扩展点——生态项只动这里（P1-1）

### 7. EC 校准区修改（0x000-0x3FF / 0x400-0x6FF）
**不做。原因：数据区，改无意义且有风险。**
- 该区域为固件校准/镜像数据（3800RPM 风扇校准多份拷贝、传感器系数表、SystemID）
- 无功能寄存器价值；写入可能破坏固件内部状态
- 只读观测（已完成穷尽扫描）

### 8. 重做反编译源码（/tmp/opencode/cc 重启后丢失）
**不做。原因：无增量价值。**
- 反编译结论已完整沉淀（ControlCenter反编译报告_20260820.md + 深度调研报告）
- 协议、寄存器、事件表全部验证闭环；重做只是重复劳动

### 9. 激进内核参数（amd_pstate=active 等）
**不做。原因：当前已是官方最优。**
- 实测 scaling_driver=amd-pstate-epp（active 模式）——网络建议的最高形态已达成
- 内核 cmdline 保持默认（无参数即最优）
- 新内核 7.0.0-29 已含全部修复（Bug 218305/amd-pstate 缓存失效等）

### 10. NVIDIA 超频/刷 VBIOS
**不做。原因：笔记本显卡厂商锁定。**
- nvidia-smi 不支持移动版 OC；VBIOS 刷写变砖风险 + 保修失效
- 当前 120W 动态 boost 已正常工作（nvidia-powerd 管理）

### 11. 蓝牙开启/常驻
**不做。原因：用户主动关闭的省电状态。**
- 蓝牙服务 inactive、AX200 断电——符合省电目标
- 需要时一键启用即可（无成本）

### 12. PPD（power-profiles-daemon）修复
**不做。原因：已被替代。**
- PPD 包在但服务文件缺失；apply_mode.sh 已覆盖全部模式切换场景
- 修复 PPD 会与 TLP/apply_mode.sh 三套并行——增加冲突面，无收益

### 13. 0x78C 直接改写（亮度/模式位）
**不做（常规使用）。原因：EC 与驱动双通道竞争。**
- 0x78C 由 EC 硬件（Fn+F6/F7）和 uniwill 驱动共同管理
- 手动改写可能在残留场景下写入错误状态（Fn 残留问题未完全定位）
- 亮度调整继续走硬件键/驱动接口（已验证正常）

### 复核新增发现（写入方案）
1. **ec_tool.py write_mem bug 修复**：/dev/mem 打开模式 rb→r+b（此前写操作全靠 WKBC 备用路径掩盖）

4. **上游动态**：2026-07/08 上游补丁重构设备描述符（TUXEDO 系列全面支持 kbd backlight+lightbar）——本机已在白名单（驱动绑定 GM5BG0E）

## 八、GPU 风扇自定义——技术否定（2026-08-20 第十轮）

### 结论：原"GPU 风扇表2 扩展"不可行，降级为不做
- **结构修正**：风扇表 = upper_temp[16]+lower_temp[16]+fan_speed[16] × CPU/GPU（96 字节 0xF00-0xF5F）——此前"表1/表2"解读有误
- 驱动 `uniwill_set_fan_tables()`：切平台模式时 `regmap_bulk_write(0x0F00, tables, 96)` **重写全部** + 0x7C6 bit2 触发 EC 重载
- 直接写 0xF50（GPU 转速表）会被任何模式切换覆盖
- 正确路径需改驱动数据结构并重编译 DKMS——收益低（4060 GPU 曲线自定义意义小）风险中——**不做**
- **实际可控面**：3 套表由驱动写死，用户可换的是平台模式选择（已有 UI）；温度墙/功耗限制由 ryzenadj 管理（已有）
