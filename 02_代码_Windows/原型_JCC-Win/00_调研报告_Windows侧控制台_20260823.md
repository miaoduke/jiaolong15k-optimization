## 二、本地资产穷尽盘点（Windows 侧）

### 2.1 官方控制台反编译成果（= 替代品的规格说明书）

架构链（反编译实锤，见 ControlCenter反编译报告_20260820.md）：

```
GamingCenter3_Cross.exe (UWP, .NET Native AOT)
    ↓ MQTT (M2Mqtt.Net.dll)
SystrayComponent.exe (.NET, 已反编译 3452 行)
    ↓ WMI/服务
GCUService.exe (.NET 12MB, 核心服务)
    ↓ DeviceIoControl: IOCTL_GPD_ACPI_ECREAD / ECRITE 等
ACPIDriverDll.dll (原生 C++ 4.1MB, SMRW: READ=0xBB / WRITE=0xAA)
    ↓
厂商 ACPI 内核驱动 (UWACPIDriver.sys, drivers_backup 有 2 个版本) → EC
```

**可直接移植的成果**：
1. **IOCTL 全集**：端口读写 / ACPI CM / EC READ/WRITE / MMIO / PCI / 温度 TMP1-3 / SmartApcTable(智能风扇表) / CustomRW —— 覆盖本机全部需求。
2. **ECSpec 寄存器地图**（官方 ECSpec.cs）：风扇 RPM 0x464/0x46B-C、PL 表 0x730-0x737/0x783-5、cTGP 0x743-6、VRM 0x753-4、PWM 0x75B-C、支持位 0x765-6、充电上下限 0x7D0/0x7B9、TCC 默认 0x7D8-DA。
3. **RGB 协议**（与我们 Linux 逆向完全互证）：颜色 0x769-76B(Level 0-50)、触发 0x767 bit5/bit7、28 种灯效枚举、MEZone_2nd_101 分区注册表布局。
4. **OSD/WMI 事件编号表**：KB_LED_LEVEL=59-63、SILENT=6/7、TPON/OFF=4/5 等（托盘通知可直接复用编号语义）。
5. **Uniwill WMI GUID 族 ABBC0F6A~ABBC0F72**（10 个）= 官方用户态接口。
6. 风扇模式字节语义：Normal=0x00 / Turbo=0x10 / FanBoost=0x40 / User=0x80 / UserLevel1-5=0x81-85。

### 2.3 OS 无关知识移植（Linux 侧逆向 → Windows 直接复用）

EC 是独立微控制器，寄存器地图与操作系统无关，以下结论**双系统通用**：

| 寄存器/机制 | 用途 | 移植注意 |
|------|------|---------|
| ECMG MMIO @0xFED50000 (4KB) | EC 扩展 RAM 直映 | Windows 用户态不可直读物理内存 → 必须经厂商驱动/内核通路 |
| PWM 0x461/0x469 | 双风扇 PWM 直写(0-200) | 连续写(≥50ms)保持，单写被 EC 覆写(~1.5s) |
| 风扇曲线表 0x0F00-0x0F5F + 门控 0x7C6 bit2 | 96B 六段表，mode 1-4 触发协议 | 写入协议照抄 Linux 验证版 |
| RGB 0x769-76B + 0x767 bit5/bit7 + 呼吸 0x7C5 | 键盘灯全套 | 0x76C-76E **非持久默认色**（三次实测淘汰） |
| 充电阈值 0x7B9(+bit7 满充标志)、下限 0x7D0 | 电池保养 | 官方控制台同款地址 |
| Fn+X 三档 | EC 硬件处理，**OS 无关** | Windows 下同样免驱动可用；档位状态不在任何可见寄存器 |
| Dynamic Boost MXDB=0x19(25W) | 140W 上限实锤 | Windows 由 NVIDIA 驱动自动管理（无需自研） |
| 读通道可靠性 | /dev/mem 直读会返回假 FF | 一切读值必须双通道交叉验证后采信 |

### 2.4 已知坑位清单（继承 Linux 侧教训）

1. **双写者冲突**：JCC-Win 与官方 CC 同时运行会争抢 EC —— 弃用即彻底卸载，或运行期检测互斥。
2. **写后必回读**：`nvidia-smi -pl` 陷阱（返回成功但墙不变）在 Windows 同样适用；所有写入回读确认。
3. **EC 覆写行为**：空闲写高 PWM 被拉回、升速斜坡/降速滞后 4-5s 是固件行为，软件不可消除。
4. **温度红线不变**：>92°C 停 / >95°C 熔断；7435H 严禁刷 7735H BIOS；不做电压操作（SMU 拒绝）。

### 3.2 关键情报一：WinRing0 已死（驱动封杀时间线）

- CVE-2020-14979（本地提权）→ 微软"易受攻击驱动封锁列表"(Vulnerable Driver Blocklist) 收录。
- 2025-03 起 Defender 波动性标记 `HackTool/VulnerableDriver:WinNT/Winring0(.B/.D/.G)`；2025-09 后再封锁且未回退。
- 受害者含 HWiNFO、Razer Synapse、SteelSeries Engine、FanControl ≤V237（被报 Trojan:Win32/Vigorf.A）。
- 行业出路 = **PawnIO**：微软签名、HVCI 兼容的单一只读签名驱动，运行经 RSA-2048 验签的 Pawn 沙箱模块；FanControl V238+(2025-04)、OpenRGB MR#2833、OmenMon v1.4.0 均已完成迁移。
- **对 JCC-Win 的约束：任何新代码不得链接/携带 WinRing0。**

### 3.3 关键情报二：PawnIO 兜底通路的硬限制

OmenMon-Reborn 迁移笔记（2026-05）披露官方模块 `LpcACPIEC.bin` 的白名单：
```pawn
is_port_allowed(port) { return port == 0x62 || port == 0x66; }  // 仅此两端口, 字节访问
```
即只能访问**传统 ACPI EC 的 256 字节窗口**。而本机关键寄存器（0x461 PWM、0x769 RGB、0x7B9 充电、0xF00 曲线表）全部在此窗口之外（EC 扩展 RAM 经 MMIO 0xFED50000 映射）。
→ **PawnIO 无法承载 JCC-Win 的控制类功能**，只可用于：(a) 未来若 ITE 分页机制被摸清后的低半区探测；(b) 与 LHM 配合的基础传感器读取。

### 3.4 关键情报三：同模具社区先例证明可行性

同方(TongFang)/Uniwill 裸模具（XMG/Eluktronics/Machenike/机械革命等贴牌）在 Windows 侧已有多个社区工具成功实现 RGB/风扇控制（TongFangRGB、open-ec-control-center、Tongfang UCC），均通过 ITE EC 通路。GM5BG0E 属同族新模具（寄存器布局更新），官方控制台反编译已给出精确地址——**可行性无悬念，工作量在工程化而非探索**。

## 四、EC 访问技术路线决策（排序）

| 优先级 | 路线 | 原理 | 优点 | 缺点/风险 | 判定 |
|--------|------|------|------|----------|------|
| **P0 主路** | 复用厂商链：P/Invoke `ACPIDriverDll.dll` 导出函数 | 该 DLL 即官方对内核驱动的用户态封装（SMRW 0xBB/0xAA + IOCTL_GPD_ACPI_EC*） | 零内核开发、厂商签名驱动已在档、寄存器全覆盖 | 需 IDA/Ghidra 枚举导出与调用约定；DLL 不随备份分发需从现机提取 | ✅ 采用 |
| P1 备路 | Uniwill WMI ABBC0F6A~F72 方法调用 (root\wmi) | 官方另一条用户态接口 | PowerShell/C# 数行即可探活 | 方法号未知需反编译对照；能力面可能窄于 IOCTL | ✅ 作为交叉验证与降级 |
| P2 兜底 | PawnIO(LpcACPIEC) | 签名安全驱动 | 无 AV 问题 | 仅 256B 传统窗口，够不到本机寄存器 | ⚠️ 仅限基础探测/监控辅助 |
| 否决 | WinRing0 / RWEverything 驱动 | 物理内存/端口裸访问 | 曾是万能通路 | Defender 封杀 + BYOVD 安全污点 | ❌ 禁用 |
| 远期 | 自研 KMDF 驱动（attestation 签名） | 自己的 EC 驱动 | 完全可控 | 需 WHQL/EV 证书成本、周期长 | ⏸ 仅当厂商 DLL 断供时启动 |

## 五、调研结论

1. **自研可行且有捷径**：官方栈三层中只有最底层（ACPIDriverDll + UWACPIDriver.sys）是必需品，上面两层（MQTT/UWP/GCUService）正是要弃用的臃肿部分；我们保留底层、重写上层。
2. **监控先行零风险**：LHM(PawnIO 构建) + NVML 可立即交付仪表盘，不碰任何写入。
3. **控制功能一步到位有依据**：寄存器地图、写入时序（连续写对抗覆写）、触发协议（曲线表 magic 0xFD/0xC9→0xC8）全部有 Linux 侧实测背书，Windows 只需换传输层。
4. **安全合规底线**：不用 WinRing0；不关闭内存完整性(HVCI)；不绕过驱动签名。
