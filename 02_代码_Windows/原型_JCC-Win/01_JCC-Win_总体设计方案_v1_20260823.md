# 01_JCC-Win 总体设计方案 v1 — 蛟龙控制中心（Windows 版）

> 日期: 2026-08-23 | 版本: v1（依据同日 `00_调研报告` 决策制定）
> 定位: 替代已弃用的官方 GamingCenter3，成为本机 Windows 系统的唯一硬件控制台
> 命名: **JCC-Win** (Jiaolong Control Center for Windows)

---

## 一、目标与非目标

### 目标
1. 单 exe、零后台服务、托盘常驻（G-Helper 式轻量哲学），冷启动 <1s。
2. 功能对标官方 GamingCenter3 的本机可用子集 + Linux 侧 JCC 已验证能力：
   监控仪表盘 / 性能模式 / 风扇曲线 / RGB 键盘灯 / 充电阈值 / 刷新率与亮度 / 档案系统(AC/DC 绑定)。
3. 所有 EC 写入走厂商签名通路；写后必回读；单写者互斥。
4. 配置 JSON 持久化，含 schema_version 与损坏恢复。

### 非目标（明确不做）
- CPU 降压/超频（SMU 硬件拒绝，Linux 三重实证）；NVIDIA OC（移动版锁）。
- 自研内核驱动（仅当厂商 DLL 断供才启动远期预案）。
- 宏/按键重映射（PowerToys 已覆盖）；音乐律动等 AP 类软件模拟灯效（价值低）。
- 遥测/联网/账号/自动更新服务。

## 二、总体架构

```
┌─────────────────────────────────────────────────────────────┐
│ JCC-Win.exe (C# / .NET 8, WPF+MVVM, 单进程)                  │
│                                                             │
│  UI 层: 仪表盘 │ 性能模式 │ 风扇曲线编辑器 │ RGB │ 档案/设置   │
│          └ NotifyIcon 托盘(左键显隐/右键快捷)                  │
│─────────────────────────────────────────────────────────────│
│  Core 层                                                     │
│   • ProfileService: profiles.json (schema_version=1)         │
│   • AcBindService: WM_POWERBROADCAST → 自动套用档案           │
│   • WriteGate: 单写者队列 + 写后回读 + 官方CC运行检测互斥        │
│   • ToastService: 系统 Toast 通知(非阻塞,替代自绘浮层)          │
│─────────────────────────────────────────────────────────────│
│  HAL 层（可插拔后端, 运行时探测择优）                           │
│   Monitor: LibreHardwareMonitorLib(PawnIO构建) + NVML/NvAPI   │
│   Control: [A] VendorDll → ACPIDriverDll.dll P/Invoke         │
│            [B] UniwillWmi → root\wmi ABBC0F6A~F72             │
│            [C] PawnIO → 仅基础探测(LpcACPIEC 0x62/66)          │
│   Display: SetDisplayConfig(刷新率) / WMI+DDC-CI(亮度)         │
│   Power:   powercfg 方案 / ryzenadj.exe 可选调用               │
└─────────────────────────────────────────────────────────────┘
```

**技术栈决策**：
| 项 | 选择 | 理由 |
|----|------|------|
| UI | WPF + MVVM（CommunityToolkit.Mvvm） | FanControl/G-Helper 同栈成熟度最高；原生控件零皮肤包 |
| 语言 | C# / .NET 8 | LHM/NvAPIWrapper/PawnIOLib 均为一等公民 |
| 发布 | dotnet publish 单文件自包含 | 免安装，U 盘可携带 |
| 托盘 | H.NotifyIcon | 维护活跃 |
| 监控 | LibreHardwareMonitorLib（PawnIO 构建）+ NvAPIWrapper | 绕开 WinRing0 封杀 |

## 三、EC 访问通路分层策略（核心章节）

### 3.0 M0 探测前置
运行 `02_probe_environment_20260823.ps1`，确认四要素：
① `ACPIDriverDll.dll` 在现机的存在路径；② UWACPIDriver 服务/驱动装载状态；
③ root\wmi 下 ABBC* 类清单；④ 内存完整性(HVCI)状态。

### 3.1 后端 A（主路）：VendorDll P/Invoke
- 目标：加载官方 `ACPIDriverDll.dll`，IDA/Ghidra 枚举导出表，定位 EC 读/写导出函数
  （对应 IOCTL_GPD_ACPI_ECREAD / ECWRITE，SMRW 参数 READ=0xBB / WRITE=0xAA）。
- C# 侧 `[DllImport("ACPIDriverDll", ...)]` 直调；DLL 随 JCC 分发目录存放（不装驱动不改系统）。
- 验证协议：读 0x740(ProjectID 应=GM5 系列 17)、读 0x464(风扇 RPM 与 BIOS 观察一致)、
  读 0x7D4 区(MXDB=0x19)。三项全对 → 后端 A 就绪。
- 失败回退 → 后端 B。

### 3.2 后端 B（备路）：UniwillWmi
- `ManagementScope root\wmi` 枚举 GUID 类 ABBC0F6A~ABBC0F72，对照反编译报告方法号调用。
- 同时作为 A 的**交叉验证通道**（同一寄存器双路读值一致性 = 反"假 FF"保险）。

### 3.3 后端 C（兜底）：PawnIO
- 仅用于基础传感器辅助读取与未来 ITE 分页机制探索；不承载控制功能（3.3 节硬限制见调研报告）。

### 3.4 写入安全规则（铁律移植）
1. 写前记录原值 → 写入 → 回读比对，不一致即回滚并告警。
2. PWM 类连续写场景由 WriteGate 以 ≥50ms 间隔守护线程维持（对抗 EC ~1.5s 覆写）。
3. 曲线表写入遵循 magic 协议：bulk 写 0x0F00 六段表 + 0x0F5D=0xFD + 0x0F5E=0xC9 → mode 写 0x0F5F。
4. 温度红线内置：任何满载类操作前检查温度 ≤75°C；监控 >92°C 告警、>95°C 熔断提示。

## 五、关键设计决策

### D1 双写者互斥（弃用官方的落地）
- 启动时检测：Appx 包(GamingCenter)/GCUService/SystrayComponent 进程与服务 → 存在则 Toast 引导一键清理：
  `Get-AppxPackage *GamingCenter* | Remove-AppxPackage` + 停止并禁用相关服务（脚本化，先备份 Appx 清单）。
- 运行期：每 30s 巡检上述进程，出现即挂起 WriteGate 并告警（防止用户重装官方后冲突）。

### D2 AC/DC 绑定（Ayuz/TCC 模式）
- `WM_POWERBROADCAST`(PBT_APMPOWERSTATUSCHANGE) 触发 → 套用 ac/bat 绑定档案（默认关闭，需用户显式开启）。

### D3 Toast = 系统通知（审计 K2 的 Windows 映射决策）
- 采用 Microsoft.Toolkit.Uwp.Notifications（桌面 Toast），不自制浮层——消除 v2-Linux 审计中"Toast 自相矛盾"问题。

### D4 profiles.json Schema v1（审计 R2 修复）
```json
{ "schema_version": 1,
  "profiles": { "办公": { "power_plan":"..., "refresh_hz":60,
      "rgb": {"color":[0,127,0],"brightness":2,"effect":"static"},
      "charge_limit":80, "fan_mode":"quiet" } },
  "power_binding": { "ac": "游戏", "bat": "办公" },
  "active_profile": "办公" }
```
- 加载损坏时：改名 `.corrupt-{timestamp}` 存档 → 从默认模板重建 → Toast 告知（审计 minor 项修复）。
- 写入采用 temp 文件 + File.Replace 原子替换。

### D5 单写者队列（审计 R1 映射）
- 所有 HAL 写操作经 `WriteGate`（进程内 SemaphoreSlim 串行）；
- 与外部脚本共存约定：JCC-Win 未运行时不产生任何常驻写入者（无服务设计天然满足）。

| 里程碑 | 内容 | 出口标准 | 预估 |
|--------|------|---------|------|
| **M0 探测**(已完成脚本化) | probe 脚本执行 + 结果回填本文档 §3.0 | 四要素结论明确 | 0.5h |

| **M2 通路验证版** | 后端 A 导出枚举+只读验证(ProjectID/RPM/MXDB)；失败转 B | 三项只读探针全通过并留档 | 1-2 工作块(+RE 时间) |
| **M3 控制版** | 功能 3/4/5/6/7 上线(写入+回读+互斥) | 每项写入回读一致;RGB/Fn+X 无冲突 | 3-4 工作块 |

## 七、验收标准（M4 出口）

- [ ] 单 exe 自包含运行，无安装器依赖，退出后零残留进程/服务
- [ ] 仪表盘数值与 HWiNFO/nvidia-smi 交叉一致（±5%）
- [ ] RGB 四类灯效写入→EC 回读→肉眼确认三重通过
- [ ] 充电阈值 80% 写入后拔插电行为符合预期
- [ ] 刷新率 165↔60Hz 切换即时生效且随档案/电源状态联动
- [ ] 官方 CC 包清理脚本执行后，Appx/服务/进程三项检查均为零
- [ ] profiles.json 断电模拟损坏后可自愈重建
- [ ] Defender 全程零告警（无 WinRing0 的证明）
- [ ] 温度红线告警在人工加热测试中触发正确

## 八、风险与回滚

| 风险 | 等级 | 缓解/回滚 |
|------|------|----------|
| 厂商 DLL 缺失或导出不可调 | 中 | 转 WMI 后端；仍不通则评估 drivers_backup 内 UWACPIDriver.sys 直接 IOCTL（需逆向 IOCTL 码）；最终预案=自研 KMDF（远期） |
| Windows 更新封锁厂商驱动 | 低 | 厂商签名合法驱动不在封锁列表；保留 sys 备份可 pnputil 重装 |
| EC 写入异常(风扇失控等) | 低 | 写前原值备份 + 一键恢复出厂曲线(mode=STANDARD 表重生成) + Fn+X 硬件兜底 |
| 反作弊软件误报 | 低 | 无内核组件、无裸端口访问；如遇个别游戏误报可加白名单 |
| 双系统寄存器语义漂移 | 低 | EC 固件唯一(N.1.23/1.30)，Linux 侧知识直接有效；固件升级后需复测 |
