### 四种架构流派
\`\`\`
①内核驱动派   : nbfc/msi-ec/LegionLinux/asusctl —— 写.sys/ko, 能力最强, 门槛最高
②WMI方法派    : G-Helper/LegionToolkit —— 调厂商WMI命名空间, 依赖厂商驱动在位
③传感库派     : FanControl/LHM —— WinRing0通用内核+软件层组装, 通用性强
④直调DLL派 ★ : 本项目 —— 官方UWACPIDriver用户态封装直调, 免管理员µs级,
                无自写内核风险, 无厂商WMI版本耦合 —— 12家中唯一的轻量安全位
\`\`\`

## 四、v6.0 目标规划

### P0 (v6.0 核心)
1. \`ec_profiles/mechrevo_gm5bg0e.json\` — 地址表外置(含版本/观测条件注释)
2. **智能风扇曲线**: 温度采样(现有µs级ReadEC) → 目标Duty写入(0x461/0x469需先验证写语义)
   - 曲线编辑器(GUI): 最多8锚点, 迟滞±3°C, 安全钳制[35%,100%]
   - 失效保护: 10s无采样或>95°C → 立即恢复自动挡
3. 充电阈值日常化: 开机自检+托盘常显

### P1 (v6.1)
4. 触发器规则引擎: 电源事件(WMI BatteryStatus) / 进程监控 → 场景切换
5. 传感器聚合模型: EC+nvidia-smi+WMI热区 → 统一SensorBus

### P2 (v6.x+)
6. 守护进程拆分(ec_daemon.py + GUI瘦客户端)
7. RGB键盘区逆向(待资料)
8. 多机型profile社区分发

## 七、数据流(风扇曲线示例)

\`\`\`
[每1s] ReadEC(0x43E) --µs--> temp
         │
    curve.lookup(temp) ──迟滞过滤──> target_duty%
         │                            │
   |Δtarget|<3%? ──是──> 跳过          │
         │否                           ▼
   WriteEC(0x461, target*2) <──钳制[70..200原始值]
         │
   [安全监视线程] >95°C 或 10s失联 → 恢复官方自动挡(SET_DETAIL FAN_AUTO)
\`\`\`
⚠️ 前置条件: Duty 写语义(0x461 是否可写/是否×2编码)必须先走
   附录D同款流程: 反汇编确认 + NO-OP实验, 未验证前不开放。

## 九、安全设计不变量(继承+新增)
1. 五步法写操作 + 白名单守卫(已落地 _addr_ok)
2. 曲线引擎任何异常 → fail-safe 回官方自动挡
3. 所有新写语义先过"静态反汇编+NO-OP实验"双关
4. 配置JSON带 schema 版本号, 非法字段拒绝加载
