## U1: AMD ACPI WMI (`AMD_ACPI`) — ⚠️ 存在但需管理员+需逆向

### 发现
- 类存在：`root\wmi\AMD_ACPI`
- 9个方法：QueryVersion / Init / GetObjectID / Getdvalues / RunCommand / GetMinMaxSteppingValues / GetDimmSpdData / GetObjectID2 / GetRmpData
- 实例：Active=True, InstanceName=ACPI\AMD0005_0

### 分析
- 这是 **AMD Platform Security / SMU 的 WMI 包装层**
- `RunCommand(Inbuf, Outbuf)` 可以向 SMU 发送任意命令（与 ryzenadj 底层相同）
- **潜在价值**：如果 SMU 命令表中有 Curve Optimizer / PBO / Eco Mode 的命令ID，理论上可以在 Windows 上直接调用
- **阻塞**：需要管理员 + 需要知道 SMU 命令ID（ryzenadj 源码有，但 7435H Rembrandt 的 SMU 拒绝了这些命令）
- **结论**：⚠️ 通道存在但 SMU 层面锁死（与 Linux ryzenadj 结论一致），**除非未来 AMD 解锁**

## U2: NVIDIA VF Curve via NVAPI — ✅ 部分可用

### 发现
- `nvapi64.dll` 可通过 ctypes 加载并初始化（`nvapi_QueryInterface(0x0150E828)` → ret=0）
- `NvAPI_GPU_GetVFPCurve` 函数指针存在
- `NvAPI_GPU_SetVFPCurve` 函数指针**不存在**（笔记本驱动可能移除了此导出）
- `pynvml` 已安装，温度/功耗/利用率监控正常

### 结论
- **VF Curve 读取**：✅ 可行（GetVFPCurve 存在）
- **VF Curve 写入**：❌ SetVFPCurve 函数指针不存在
- **替代方案**：MSI Afterburner（通过 RivaTuner 内核驱动绕过 NVAPI 限制）
- **GPU 降压仍需 Afterburner**，纯 Python 路径不可行

## U5: Battery Boost via NVAPI — ❌ 函数不存在

- `NvAPI_D3D_SetBatteryBoost` 函数指针不存在
- Battery Boost 是 Optimus/TGP 管理的一部分，可能通过 GCUService MQTT 控制
- **MQTT 路径**：`GPU_DynamicBoost` 已可调（5-25W），但 Battery Boost 是独立功能
- **替代**：限制 TGP 到 115W 即等效 Battery Boost
