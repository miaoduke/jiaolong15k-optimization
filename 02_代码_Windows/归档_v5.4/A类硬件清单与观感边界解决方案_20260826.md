## 二、观感边界"完全解决"穷尽调研(五方案)

先量化边界本身: G-Helper UI = 自绘 WinForms, 全部观感来自 **12 个小控件文件共约47KB**
(RButton 7.4KB圆角钮 · RForm 4.8KB暗色窗体 · Slider 9KB · RComboBox 13.4KB · RChart 1KB曲线 ·
RTrackBar/RCheckBox/NumericUpDownWithUnit 等) —— **体量极小, 是可被整体移植或逐行仿写的对象**。

| 方案 | 技术路线 | 观感还原度 | 新增依赖 | 工作量 | 许可证 | 判定 |
|------|---------|-----------|---------|--------|--------|------|
| **F1 直接 fork G-Helper** | C# 源码内替换硬件层(AsusACPI→ACPIDriver桥), UI 原封 | **100%(就是本体)** | .NET SDK 编译(GH Actions 云编译免装) | 高(理解44MB代码) | **GPL-3 传染**: 我方分发须同开源 | ⭐⭐⭐ 观感满分但工程重、许可受限 |
| **F2 C# WinForms 重写壳**(系统自带 .NET 4.8) | R*控件逐行移植(源码在手!), 后端走 IPC 调 Python | ~98% 同栈同级渲染 | 零运行时(Win10/11 自带 4.8) | 中 | GPL 仅约束移植文件的衍生性(私用无碍; 分发需开源UI层) | ⭐⭐⭐⭐ **观感/成本最优平衡** |
| **F3 PySide6(Qt)** | QSS 复刻暗色圆风+QML 动画 | ~95% 可超越(动画) | pip PySide6(~200MB) | 中 | LGPL(动态链接商用友好) | ⭐⭐⭐⭐ 开发效率最高 |
| **F4 Tkinter + sv-ttk(Win11主题)+Canvas自绘** | 现有栈极限自绘 | ~85%(字体渲染/DPI/微动画有差) | pip sv-ttk(小) | 低 | 免费 | ⭐⭐ 上限明确, 无法"完全" |
| F5 Web 壳(pywebview+WebView2) | HTML/CSS 任意绘制 | ~99% | WebView2(Win11自带)+pywebview | 中高(双端通信层) | MIT | ⭐⭐⭐ 曲线编辑器最爽, 但托盘/OSD 需额外原生胶水 |

### 结论与推荐
- **"完全解决"在工程上有两条真路: F2(同栈移植) 与 F5(Web壳)**; F3 为高效近似(95%); F4 承认上限。
- **推荐组合拳**: 
  - **S1-S2 先用 F4(Tkinter+sv_ttk) 快速点亮全部 ✅ 功能**(不阻塞业务);
  - **S3 起 GUI 层切换 F2**: 把 RButton/RForm/Slider/RChart 四个核心控件(合计~22KB)逐行移植为 C# WinForms 壳,
    经命名管道调 Python 引擎(FanControl 自己就是 GrpcDotNetNamedPipes 双进程架构, 先例成熟);
  - F2 的 GPL 注意点: 若未来公开分发, UI 层按 GPL-3 开源即可(本项目本就开源精神), 私用完全自由。
- 该组合让"观感完全解决"从口号变成两阶段交付: 第一周可用版, 第二阶段像素级版。
