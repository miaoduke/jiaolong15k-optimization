# 待解锁(🔶)与B类(🔴) 科学实现路线图
**日期**: 2026-08-26 · 前置澄清: Keystone=NFC钥匙≠机身SD存储卡槽, A类判定不变
**原则**: 除硬件物理不存在/不支持外, 每项给出可执行的科学路径; 全程先NO-OP后真写

## 一、🔶 待解锁项 — 六步实验模板统一套用
> 模板(附录D同款): ①读原值记录 → ②写回同值(NO-OP)→读回比对 → ③监控collateral地址无漂移
> → ④小步真写→延时→读回 → ⑤物理世界验证(看得见的变化) → ⑥恢复原值+登记

### U1 CPU/GPU 风扇曲线(S2核心·一步之遥)
- 已证: 地址双镜像(0x461≡0x75B)·编码raw÷2·RPM自洽
- 实验: NO-OP(0x75B写60读60) → 真写 raw=78(39%) → 10s后RPM应下行 → 恢复60
- 仲裁: 写前经MQTT把官方风扇切手动/固定挡, 退出曲线回AUTO(GCUBridge会覆盖直写)
- 验收: 设定duty与5s实测差≤±2% · RPM响应方向正确 · GUI断开30s自动回AUTO
### U2 Custom档功耗墙(0x783/0x784/0x785)
- 实验: NO-OP(写回65) → 真写PL1=80 → MQTT/powercfg侧读数应同步变80 → 恢复65
- 风险: 模式切换时固件重写墙值 → 曲线引擎同款哨兵监听
- 验收: 三路读数(EC/MQTT/nvidia-smi无关但EPP联动)一致
### U3 触摸板禁用(0x7A6)
- 协议(roj234实证): bit6=开关 · bit3=LED(两处均为干净独立的读改写函数)
- ⚠️审计修正: 此前引用的"模式段0xC7"实为 roj234 set_battery_mode 内的残缺代码(构造的val未写入,行710直写mode参数——系其自身bug), 不采信; 且提示该地址可能被多功能复用, 写实验时须全字节比对
- 实验: NO-OP → 写bit6=1禁用 → 物理验证触摸板失灵 → 恢复
- 兜底: 失联自恢复定时器(60s强制还原,防锁死外设)
### U4 键盘背光三档(0x78C bit5-7)
- 协议: 档位=(val>>5)∈{0,1,2}; 写法 val=(val|16)&31|((档)&7)<<5
  ⚠️审计披露: 该写法会强制置 bit4=1(roj234原码行为, 含义未知——疑为"手动使能"位), NO-OP阶段需先单独验证 bit4 置位是否引起副作用
- 本机现状: 读数8 → 当前档0(熄灭或微亮)
- 实验: NO-OP → 写档2 → 目视键盘亮起 → 回档0 — **风险最低, 建议第一个做**
### U5 关机USB充电(新发现!)
- 协议: REG_TRIGGER(1895=0x767) 命令触发器, 写"2+(b&0xFD)"清bit1触发切换
- 附带: LightBar/WinKey锁同走此触发器
- 实验: NO-OP → 触发 → 关机态插手机看是否充电 → (EC级功能, OS不参与)
### U6 Display组(零内核风险·纯Windows API)
- 刷新率✅已通 · ICC色域(ColorProfileHelper思路: 枚举/安装/激活profile, 需EDID定面板能力)
- 合盖行为(powercfg LIDACTION) · 亮度(WmiMonitorBrightnessMethods, 科学测试已验)

## 二、🔴 B类 — "异址待逆向"的科学破法
### B1 Fn锁 / Fn组合键自定义
- 本机证据: roj234 地址 1870(0x74E) 于本机实测返回 None(第二轮验证), 故 Fn 控制在本模具异址
- 路径: **DSDT表ERAX字段图**(imini方法论):
  ①ACPICA acpidump.exe(Intel官方Win版单文件)dump DSDT
  ②iasl -d反编译DSL → grep \`OperationRegion(...EmbeddedControl)\`全字段图
  ③定位Fn相关Field偏移 → 映射为EC RAM地址 → **只读观察法**: 按Fn键前后采样比对锁定真址
  ④锁定后再走六步模板
- 组合键自定义的硬上限: 若Fn事件由固件直接发PS/2/HID且无可编程键位区, 则属**硬件不支持**, 如实归A'
### B2 键盘RGB流光
- 先做**硬件能力确认**(非逆向): ①官方控制台灯效页截图级检查 ②USB描述符/HID collection枚举 ③DSDT键盘区字段宽度
- 判定树: 若EC口仅三档背光(0x78C形态)→硬件不支持,归A'; 若存在per-key区→OpenRGB社区协作路径(提交机型探测数据)
### B3 TGP/DynamicBoost等效替代
- EC 0x743活体(bit图样待解) + nvml API(nvidia-smi层) 双路并进; nvml路零内核风险先行

## 二·五、审计连带新发现(登记待验)
- **0x742 bit4 = 充电限制门控**(roj234 get_battery_limit 先查此位): 我方 0x7A8/7A9 能直接读到阈值, 说明本机门控已开; 写实验前应先核对此位
- **电池电压三档模式**(长续航-50mV/标准-100mV/工作站-200mV): roj234 实现存在明显bug(val未写入), 功能真实性与正确地址待独立验证——列为 U7 候选
- roj234 充电限制兼容性 workaround(0x07C3/0x0770 读值判断): 若未来写充电阈值遇阻可参考
