## 二、破解的通信协议（自制控制台的核心钥匙）

### 2.1 MQTT 接入凭证（实测验证 ✅）
| 参数 | 值 |
|------|-----|
| Broker | `127.0.0.1:13688`（GCUBridge监听0.0.0.0） |
| 协议 | MQTT 3.1.1，载荷JSON明文 |
| ClientId公式 | `PluginClient_N`（N=0~19，插件专用通道） |
| Username | `PluginClient_User_N` |
| Password | `PluginClient_Pwd<REDACTED>[REDACTED]_N` |
| OC工具账号 | `OcToolUser` / `OcToolPwd_[REDACTED]` |
| AES密钥 | `AES_KEY_[REDACTED]` |
| 提取方法 | PowerShell反射加载GCUBridge.exe读私有字段（脚本已存档） |

### 2.2 命令模式
```
发布 → {"Action":"GETSTATUS"} 到 Xxx/Control
接收 ← 完整状态JSON 于 Xxx/Status
```

### 2.3 Topic 全集（抓包实证）
| Topic | 功能 |
|-------|------|
| Fan/Control ↔ Fan/Status | 性能模式/PL/TGP/OC/风扇曲线 全量 |
| Setting/Control ↔ Status | Win键锁/独显直连/OSD/显示模式/Fn键/触控板/AC恢复 |
| BatteryProtection/Control | 电池保护策略 |
| System/* | GPU信息、关机、硬件监控 |
| Keyboard/Ctrl, MyRgbLightbar, HidLightbar_* | 键盘灯/灯效 |
| LCHWOC/* | 液冷超频 |
| Customize/*, Languages/*, OSDTpDetect/*, TouchPadWorkArea/* | 其他 |

### 2.4 Python 最小示例
```python
import paho.mqtt.client as mqtt, json
c = mqtt.Client(client_id="PluginClient_5")
c.username_pw_set("PluginClient_User_5", "PluginClient_Pwd<REDACTED>[REDACTED]_5")
c.connect("127.0.0.1", 13688)
c.publish("Fan/Control", json.dumps({"Action":"GETSTATUS"}))
```

## 三、EC 寄存器地图（2026-08-30 穷尽审计修订版）

> ⚠️ **修订说明**：本表原始版本以「Windows符号 × Linux实测 双重确认」为凭，经逐行对照同目录 `EC与ACPI参考/uniwill-acpi.c`（Linux 内核驱动源码）后，发现 **7 处矛盾**及多处「双方一致」标注失实。下表已按驱动源码为准勘误；与 README 最新纠错（0x44F→0x44C、0x7A6=实时功率、0x7A8/0x7A9 废弃）同步。

| 地址区段 | 原声称功能 | uniwill-acpi.c 定义（出处行号） | 审计判定（2026-08-30） |
|---------|-----------|-------------------------------|------------------------|
| 0x43E | CPU温度 | `EC_ADDR_CPU_TEMP` (:87) | ✅ 三方一致 |
| 0x44F | GPU温度 | `EC_ADDR_GPU_TEMP` (:89) | ⚠️ **已废弃**（README:67 改为 0x44C；22°C 反向读数待仲裁）；本站点旧称「Linux DSDT」实为 uniwill-acpi.c |
| 0x461/0x469 | 风扇PWM直驱 | **未定义**（驱动 PWM=0x075B/0x075C 读；唯一可写=0x1804/0x1809, 注释"unstable, only via WMI" :157-159,293-301） | 🚨 **与源码冲突**；现役 mr_ec_hw 仍按 0x461 读 duty（实测可用不代表定义正确），建议实机复核 |
| 0x464/0x46C | 风扇RPM | `0x0464/0465`、`0x046C/046D` (:94-100) | ✅ 一致 |
| 0x730-0x737 | 三档PL默认值 | **无定义** | ⚠️ 原标注「双方一致」失实，无源码佐证 |
| 0x743-0x747 | 用户风扇5档PWM | **`0x0743=CTGP_DB_CTRL`、0x744-746=cTGP/TPP/DB 偏移(NVIDIA cTGP)** (:123-140) | 🚨 **定义相反**——实为显卡功耗控制，误写有硬件风险 |
| 0x751 | 风扇控制字节 | `FAN_LEVEL_MASK GENMASK(2,0)`、TURBO/HIGH/BOOST/USER (:150-155) | ✅ 一致 |
| 0x753-0x754 | CPU VRM电流限制 | **无定义** | ⚠️ 原「双方一致」失实，无源码佐证 |
| 0x765/0x766 | 硬件支持位 | (:162,172) | ✅ 一致 |
| 0x769-76B + 0x767 | RGB颜色Level+触发位 | (:196-200, :179) | ✅ 一致 |
| 0x76C-76E | 出厂默认色(只读) | **无定义** | ⚠️ 无源码佐证 |
| 0x783-785 | PL1/PL2/PL4设置值 | (:216-220) | ✅ 一致 |
| 0x786 | TCC温度墙偏移 | **`EC_ADDR_FAN_DEFAULT`** (:222, FAN_CURVE_LENGTH=5) | 🚨 **定义相反**——实为风扇档默认表，误写有风险 |
| 0x789/0x7B9/0x7D0 | 充电阈值上/下限 | 仅 `0x07B9=CHARGE_CTRL`(阈值 GENMASK(6,0)、REACHED BIT(7)) (:257-259)；**0x789/0x7D0 不存在** | ⚠️ 原「双方一致」失实；README 仅保留 0x7B9/0x7D0 且注明固件不执行软件限充 |
| 0x78C | 键盘亮度/电源/单键背光 | `KBD_BRIGHTNESS GENMASK(7,5)` (:225-230) | ✅ 一致 |
| 0x7A6 | （原表未载） | `OEM_4` 标志位（OVERBOOST_DYN_TEMP_OFF 等）(:253-254) | ✅ **实机仲裁(2026-08-30)定案：可写标志位**——写 bit6 成功回读一致后可恢复；CPU 满载 GPU 功率上升而 0x7A6 恒=9 零响应，判据不支持「实时功率」，支持现役 mr_gui_v6 触摸板 bit6 用法 |
| 0x7E6-7E7 | 液冷水泵/风扇值 | **无定义**；且抓包 `Customize/SupportInfo: LiquidCoolingSupport=0` | ⚠️ 本机无液冷，该行描述的是不存在的硬件 |
| 0xF00-0xF5F | 智能风扇表×6块 | `0x0F00/0F10/0F20/0F30/0F40/0F50` 六表 (:281-291) | ✅ 一致 |
| 0x7A8/0x7A9 | （原表未载） | — | ⚠️ README:72 判为早期误判地址，已废弃 |
| 合计 | **147个ADDR_符号** | Linux 侧 EC_ADDR_* 定义约 **60 个** | ⚠️ 口径未区分（Windows符号穷尽 vs Linux驱动），引用时须注明口径 |
| 0x4A6/0x4A7、0x742/0x07C3 | （原表未载） | 未定义 | ⚠️ 孤儿寄存器：jcc-sudo-wrapper get-cycles 读0x4A6/0x4A7；charge_limit.sh 头注释 0x742/0x07C3—全仓库无文档 |

## 四、本机硬件边界（服务端权威数据，抓包获得）

### 4.1 功耗/性能边界
| 项目 | Min~Max | 本机状态 |
|------|---------|---------|
| CPU PL1 | 10 ~ **80W** | 已在原厂上限 |
| CPU PL2 | 10 ~ **80W** | 已在原厂上限 |
| CPU PL4 | 10 ~ **100W** | 已在原厂上限 |
| GPU 核心频率偏移 | 0 ~ **+250MHz** | ✅ 可用 |
| GPU 显存频率偏移 | -1000 ~ **+1000MHz** (HWOC ±1800) | ✅ 可用 |
| GPU TGP | **固定115W**（min=max） | ❌ 锁死（DynamicBoost 5~25W 自动补偿） |
| GPU 目标温度 | 75 ~ 87°C | ✅ 可调 |
| 内存超频 | Support=0 | ❌ 不支持 |

### 4.2 降压/超频最终判定
| 目标 | 判定 | 依据 |
|------|------|------|
| **CPU降压** | ⛔ **不可能** | OffsetCoreVoltage区间[0~0]=Intel专属；AmdOverClockSupport=0；SMU三层拒绝(Linux侧ryzenadj实测set_coall/enable_oc/oc_volt全部rejected) |
| CPU功耗调整 | 已到顶 | Windows无ryzenadj等价物；Linux生态已覆盖 |
| **GPU超频** | ✅ **可行** | 核心+250MHz/显存+1000MHz；路径=控制台UI滑条 或 MSI Afterburner 或 MQTT指令 |
| **GPU降压** | ⚠️ 唯一未测路径 | 控制台无此功能；**MSI Afterburner VF曲线优化器**在RTX4060 Laptop通常可用，值得尝试 |
| GPU功耗墙 | 部分 | nvidia-smi -pl 140 报错N/A但驱动上限140W存在（115默认），Dynamic Boost自动管理 |

## 九、经验教训表

| 教训 | 详情 |
|------|------|
| 配置文件≠硬件生效 | JSON写入成功但服务端按Min/Max钳制，SMAPCTable才是真实状态 |
| 风扇表不可直接改 | 运行时工作副本+严格校验，越界即UI隐藏；只走MQTT正规通道 |
| UI隐藏≠可解锁 | 三层门控中EC支持位是硬门槛，改配置无法穿透 |
| AOT程序集的替代方案 | 字符串穷尽提取效果接近反编译；.NET程序集可PowerShell反射 |
| 凭证藏在实例字段 | costura解包+反射读取私有字段=无需反编译器 |
| 版本升级影响协议 | GCUBridge更新可能换密码盐值，升级后需重跑 `dump_cred.ps1`（私有取证脚本，🔒） |
