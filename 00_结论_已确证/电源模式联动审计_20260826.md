# 电源模式软硬件联动审计 (2026-08-26)

> 问题：当前电源模式在本机生态中是否做到软硬件联动最佳优化？
> **结论：否。六层电源栈中仅 EC/MQTT 层单线正常，其余各层存在死亡、越界、内战或脱钩。**

---

## 一、六层现状实测（20260826 取证）

| 层 | 组件 | 实测状态 | 判定 |
|----|------|---------|------|
| L1 滑块overlay | ActiveOverlayAc=961cc777 / Dc=ded574b5 | 微软官方映射: **AC挂的是Better-Battery(省电)overlay，DC挂的是Best-Performance overlay——方向装反**；且高性能计划激活时滑块UI本应失效但overlay仍在生效 | 🔴 异常 |
| L2 传统计划(高性能) | EPP 25/80·Boost 2/0·MinState **100**/5·MaxState 100/80 | MinState AC=100 禁止深度idle(纯负优化)；Class1/2 DC MaxState=100 与基础层 DC=80 打架 | 🟡 半残 |
| L3 SMU(ryzenadj) | mr_daemon(PID14812,免管)+v6\ryzenadj全套 | daemon非admin→WinRing0加载失败→**SMU层实际死亡**；即使提权，Defender封锁WinRing0.sys；profile数值 gaming fast/slow=150W、turbo=200W **超出PPT FAST硬件上限100W**(PM Table实测)→纯装饰值 | 🔴 死亡 |
| L4 EC/MQTT模式 | OperatingMode=TURBO, EC PL1=80/**PL2=150/PL4=200** | 模式切换✓工作；但PL2/PL4是旧补丁/测试残留(原厂80/100)，roj234证实该址写入会驻留→**EC被历史写入污染** | 🟡 污染 |
| L5 GPU | vBIOS 115W锁(nvidia-smi拒绝✓双会话确认)；NVAPI PS20可写未接联动；DB自动 | 与模式切换零联动 | ⚪ 脱钩 |
| L6 风扇 | EC表随模式自动切换(FanBoost=0) | ✓ 正常，官方管理 | ✅ |

## 二、联动断裂点（按严重度）

1. 🔴 **SMU层死亡**——唯一能真正改CPU功耗曲线的软件通道不通。修法已备好：`v6\ryzenadj\installServiceTask.bat + readjustService.ps1(24KB)` 就是现成的SYSTEM计划任务持久守护方案（开机+周期重申，抗GCUService/固件重置），**装而未启**。
2. 🔴 **Windows三层内战**——overlay(省电)×计划EPP25(激进)×Class覆盖(矛盾值)同时作用，最终生效值不可预测。修法二选一：回Balanced计划用滑块（微软正道）或高性能计划+显式把两源overlay都设为MaxPerformance(`powercfg /overlaysetactive ded574b5-...` 待验证)。
3. 🟡 profile数值越界：smu_profile gaming150W/turbo200W 应改为 ≤80/≤100/≤100（STAPM 80W 是 99°C 撞墙实证的物理墙）。
4. 🟡 EC PL残留：应按档显式写 0x783-785（写后驻留已 VERIFIED-HELD），清除 150/200 污染。
5. 🟡 MinState AC=100 改回 5%（对性能无损，对功耗/热立竿见影）。
6. 🟡 多写者无仲裁：GCUService(K8模式切换reload profile) × mr_daemon × 手动bat × GHelper-MR——需单一 orchestrator + 写前进程检测（JCC WriteGate 设计已有）。
7. ⚪ GPU温度址 0x44C vs 0x44F 两轮交叉验证相反（本轮读数22°C低于环境温度，疑0x44C亦不可信）→ 反馈精度缺口。
8. ⚪ 潜在更优通道未探测：AGESA ALIB `_SB.ALIB Fn0x0C`(DPTCi)=OEM实现SPL/PPT/tctl的底层规范路径（Linux内核RFC 2026），可在DSDT中查找。

## 三、最优联动蓝图（目标态）

```
单一触发源(GUI按钮/Fn/自动化)
  ├─ EC/MQTT: OPERATING_*_MODE + PL直写0x783-85(值经HW钳制: office35/gaming80/turbo80, FAST≤100)
  ├─ SMU: ryzenadj-SYSTEM守护任务(开机+300s周期重申) ← installServiceTask.bat 现成
  ├─ Windows: 每档写EPP(office90/bal60/game25)+Boost(2/0)+MaxState(100/80)+MinState(5)
  │            overlay统一AC=MaxPerformance,消除三层内战
  ├─ GPU: NVAPI PS20 offset(game档启用) + DB保持自动
  └─ 风扇: MQTT曲线随档(官方栈已✓)
```
