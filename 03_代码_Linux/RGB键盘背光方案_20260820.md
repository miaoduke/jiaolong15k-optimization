# 键盘 RGB 背光方案（2026-08-20 验证完成）

## 结论
- **协议彻底破解**（来源：ControlCenter 5.17.49.19 自带 DefaultTool 未混淆反编译 + 实测验证）
- 静态颜色、彩虹、呼吸全部可控；**Fn+F6/F7 硬件亮度保留**（关键）
- 本机键盘类型：**SingleZone 单区 RGB**（0x766 bit2=1，0x766=0xB4）

## EC 寄存器协议
| 地址 | 名称 | 说明 |
|------|------|------|
| 0x769/0x76A/0x76B | RGB LEVEL | 颜色等级 0-50（=RGB值/5），红=50/0/0、青=0/50/50、白=50/40/40 |
| 0x767 | 模式/触发 | **bit5(0x20)=颜色应用触发**（读改写置位，EC 消费后清零=应用成功）；bit7(0x80)=彩虹 |
| 0x7C5 | 呼吸 | bits0-2=呼吸颜色索引(1-4)，写前 &0xF8 |
| 0x78C | 亮度/电源 | **bit4(0x10)=软件亮度接管（置位会破坏 Fn+F6/F7，勿碰）**；bit1=电源开关；bits5-7=亮度(bit7=4级/bit5+6=3/bit6=2/bit5=1)；bit3=硬件模式标志(EC Fn 调节时=1) |
| 0x76C-76E | DEFAULT 色 | 出厂默认（只读，本机 00 32 32=青） |
| 0x78E | SUPPORTPOWER | 电源开关支持位(0x6C) |
| 0x782 | BIOS_OEM_BYTE2 | bit6=键盘电源（Windows 非 China 模式设置） |
| 0x766 | 类型检测 | bit2=SingleZone |

## 关键坑
1. **颜色是 Level(0-50)，写 255 超值域=无效且会破坏 Fn**（之前全部失败根因）
2. **0x767 触发必须读改写**（直接写 0x20 会清掉 bit7 等其他位）
3. **0x78C 写亮度=置 bit4=软件接管 → Fn+F6/F7 失效 → 只能重启恢复**（EC 固件无软件退出接管路径）
4. **/dev/mem 读 0x760-0x78E 重启后全空洞**，必须用 ACPI 方法 `\_SB.AMW0.RKBC/WKBC`（参数 lo,hi；RKBC 返回 40 字节 buffer 首字节=值）
5. TUXEDO 的 0x1801/0x1803/0x1805/0x1808 协议是另一个方案（写 0x1801 也会破坏 Fn），仅作对照参考

## 验证记录
- 2026-08-20 晚：写 50/0/0+触发 → **变红 ✓**；Fn+F6/F7 亮度正常 ✓（0x78C 保持 0x28/0x08 硬件模式）
- 触发位消费：0x767 0x20 → 数秒后 0x00（应用完成信号）

## 内核级方案（2026-08-20 深夜完成，推荐使用）

### dkms 1.1：uniwill-laptop 移植上游键盘背光
- 补丁：`uniwill-kbd-backlight.patch`（251 行，基于 linux-next [PATCH v2] Enable kb backlight）
- 接口：`/sys/class/leds/uniwill:multicolor:kbd_backlight/`
  - `multi_intensity`：写颜色 Level（0-50），如 `echo "50 0 0" > multi_intensity` 红
  - `brightness`：**只读镜像**（0-4，跟随 Fn+F6/F7 实际值）
  - 0x000000 = EC 恢复出厂默认色（上游 workaround 写 0x010101）
- **关键适配**：亮度写被移除（不写 0x78C KBD_APPLY）→ Fn+F6/F7 硬件模式永不破坏
- 上游协议与我们逆向完全一致（0x769-76B / 0x767 bit5 / 0x78C 位定义互相印证）

3. 开机恢复颜色：开机脚本写 LED class 或 ec_tool（亮度无法软件恢复，EC 限制）

## 开机恢复（2026-08-20 深夜完成，模拟链路已验证）
- kbd-rgb-save.service：关机 ExecStop 读 EC 0x769-76B → /var/lib/kbd-rgb/state
